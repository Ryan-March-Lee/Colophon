# Colophon · 检索模型（冻结稿）

> 状态：**已定**。实施前不再改；要改先改本文，再改代码。
> 本文只定检索、首页与标签分组；阅读器、元数据抓取、AI 问答维持原样。

---

## 0. 一句话

**首页是检索台。空条件 = 浏览全库，有条件 = 检索结果；两者是同一个页面的两种状态，不是两个视图。**

产品的分界不在「首页有没有搜索框」——哪个文献软件都有。分界在于两件事：

1. 检索的索引是**用户自己写的分类学**（标签 → 分组），不是软件预置的字段；
2. 检索是**确定的布尔运算**，不是相关度排序。

这两件事任何现成软件都不可能替用户预置，所以这一层无法被复刻。

## 1. 检索语义

### 1.1 结构

- **组（group）** 是唯一的布尔单位，组内可以有多个「项（term）」。
- 每个组一个操作符：

| 组类型 | 操作符 | 说明 |
|---|---|---|
| 标签组 | 任一 / 全部 / 排除 | 三个都有 |
| 属性组（年份、阅读状态 / 星标） | 任一 / 排除 | **没有「全部」**：属性取值互斥，选「全部」等于空条件 |
| 未分组（虚拟组） | 任一 / 全部 / 排除 | 与标签组同构 |

- 组间固定 **AND**。没有跨组 OR，没有全局 AND/OR 开关。
- 空组（没选项）= **不参与**，不产生恒真或恒假。

### 1.2 求值

设组 `G` 的选项集合为 `T`，条目的组内命中 = 该条目满足 `T` 中至少一项。

| 操作符 | 组条件 |
|---|---|
| 任一 (`any`) | `G(x) = x 满足 T 中至少一项` |
| 全部 (`all`) | `G(x) = x 满足 T 中每一项` |
| 排除 (`none`) | `G(x) = ¬(x 满足 T 中至少一项)`，即 **¬(A∨B)** |

结果 = 所有非空组条件的 **AND**，再与文本搜索、当前模式（若有）取 AND。

### 1.3 年份组

年份组是一个普通的组，项有两类：

- 区间项：`{"range": [2019, 2021]}`
- 未知项：「年份未知」

两者都是项，组内 OR。因此：

- 只选区间 → 只命中区间内的已知年份，**年份未知的条目不命中**；
- 区间 + 未知都选 → 命中「区间内 ∨ 没有年份」；
- 只选未知 → 只命中没有年份的。

**补丁规则（必须实现）**：年份组处于生效状态（`T` 非空）且 `T` 里没有未知项时，组脚右侧出现一个小三角 `▸ 未知 N`；悬停 / 键盘聚焦时展开为「另有 40 篇年份未知」，点击即把未知项加入该组。

- **不默认加，不静默丢。**
- 三角**常驻**，不随结果多少而隐藏——弱化的是形式，不是存在。它是唯一的可见纠正入口。
- 三角本身也是可点击控件（不只靠文字），带 `aria-label`。

排除操作符仍按 ¬(A∨B)：只选区间 + 排除 → 排除区间内的条目，年份未知的保留。

### 1.4 作者 / 单位

**不进组区**，因为它们不进布尔网格：基数会失控（几百个名字），且无法用「任一 / 全部 / 排除」去点。

- 走顶栏文本搜索（搜 `authors` 全名）；
- 组区之外的「作者选择器」：输入几个字符定位到具体作者，选中后作为一条 AND 条件挂在表达式尾部，可单独移除。

单位同理，v1.1 再谈是否给选择器。

### 1.5 明确接受的限制

1. 组内不能「要 A 不要 B」——否定只能整组取反，或另开一个组放排除项。
2. 不能跨组 OR——真需要就把两组标签并进同一个组（那本来就是同类概念）。
3. 不能按相关度排序——因为布尔是确定的。补偿在 `§3`。

## 2. 计数

**一次遍历算全部**。禁止沿用现在的写法（`web/index.html` 的 `countFor` 对每个标签值重算一遍全库过滤）。

实现位置：`web/retrieval.js` 的 `evaluate(items, filters)`。上面的布尔求值、下面这张表的每个数字、组脚、年份未知三角、近失（§3）都在同一次 `items` 循环里算完，与组数和项数无关，只与篇数成正比。

| 位置 | 含义 |
|---|---|
| 组脚（任一 / 排除） | 该组作为子句生效后，**整体**剩余篇数 |
| 组脚（全部） | 当前已选项组合的剩余篇数 |
| 项（任一 / 排除） | 全库中满足该项的篇数（绝对值） |
| 项（全部） | **边际值**：把这个项也加上后剩余篇数 |
| 计数行 | 结果数 / 全库数 |

组脚数字必须和计数行对得上：同一组是最后一个非空组时，两者相等。

## 3. 零结果

严格布尔必然出现零结果。零结果不做「猜你想搜」，做**近失**：

按「从当前条件里去掉某一项后能救回多少篇」倒序列出，最多 5 条，每条可一键应用：

```
没有符合这些条件的文献
去掉「算法组 · 记忆多项式」能救回 3 篇
去掉「2019–2021」能救回 8 篇
把「年份未知」加入能救回 40 篇
```

规则：只对**当前选中的项**做单点移除测试；不组合、不猜测、不改写条件。

## 4. 首页结构

自上而下，只有这六层：

1. **顶栏**：搜索框（`/` 聚焦）、导入、标签库、设置、主题。导入是普通按钮，不占首页主位。
2. **组区**
   - 第一行：属性条（年份、阅读状态 / 星标），**常驻一行**，横向排布，不折叠。
   - 之后：标签组，**最多两行**（网格铺满宽度）；超出的收进「更多组 N」。展开「更多组」临时占位，不改变上限规则。
   - 末尾：**未分组固定末尾**，不参与排序，永远可见。
3. **动作条**：`未打标 N · 去整理 ›`、`待补全 N · 去补全 ›`。这是入口，不是筛选器（见 `§5`）。
4. **表达式条**：用中文复述当前布尔条件，只读；点击某段跳回对应组。右侧挂「放宽建议」（近失）与「清除」。
5. **计数行 + 列表**：`N 篇 · 全库 M`、排序、结果列表（紧凑行，见 `§6`）。
6. **详情抽屉**：点行才滑出，**不常驻**。未选中时列表吃满宽度。

组区的硬约束：**两行标签组 + 一行属性条 + 一行动作条**，合计不超过 ~4 行。超过就挤掉列表，检索台即失败。

## 5. 未打标 ≠ 未分组

两个词不许混用。

| 词 | 定义 | 形态 |
|---|---|---|
| **未打标** | 条目身上**一个标签都没有** | **模式**（不是筛选器、不进布尔、不可存为视图）。进入后是未打标队列，逐篇跳进阅读器打标 |
| **未分组** | 有标签，但该标签**没有归到任何组** | **虚拟组**，是真实的布尔组，可检索、可排除，组头带「整理」标记 |

- 未分组**没有数据库行**：`NOT EXISTS (SELECT 1 FROM tag_group_member WHERE tag_id = ...)` 即未分组。不可重命名、不可删除、不出现在「新建标签时选组」的列表里。
- 未分组只承接两处来源：AI 建议采纳的标签、导入 / 历史遗留的标签。
- 标签删除或组删除后，标签落到未分组，不会消失。

## 6. 结果列表

紧凑行，一屏 12–20 条：

```
● 标题（衬线，单行省略）
                                        2021 · IEEE TMTT        [标签] [标签]
```

- 识别锚点：**标题**。第二行**不承载任何概括**：一篇文献的技术细节写不进一行，硬写会变成第二个分类轴。标签就在行内。
- 无年份的行在年份位显示 `年份待补`（警告色），不显示空白。
- 行内标签最多 2 个（按组顺序、组内计数），超出用 `+N`。
- 行尾**不提供**打标入口：标签只在阅读器右侧栏加（见 §15）。未打标的行点进去就是详情，从详情「打开原文打标」进阅读器。
- 详情不常驻；阅读状态用 5px 圆点（待读灰 / 在读警示色 / 已读绿）。

## 7. 文本搜索

匹配字段：`title`、`abstract`、`venue`、作者全名、标签名、**`note_md`**。

- 现在是子串、大小写不敏感，与布尔条件 AND。
- **`note_md` 必须进检索**：与标题、摘要、出处、作者全名、标签名一起，落在 `web/retrieval.js` 的检索文本里（一次预处理，搜索时不再拼字符串）。
- 一篇文献**没有**「一句话概括」字段：概括一篇文献等于丢掉它涉及的细节，而标签才是它的身份。
- 全文（PDF 文本层）在接入后单独加入，并标注「全文」来源。

## 8. 数据模型

新增两张表，不动 `item` / `tag` 的既有列，因此老库靠 `IF NOT EXISTS` 自动获得，不需要迁移工具。

```sql
CREATE TABLE IF NOT EXISTS tag_group (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  color       TEXT NOT NULL DEFAULT '',
  position    INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL,
  deleted_at  TEXT
);
CREATE UNIQUE INDEX IF NOT EXISTS ux_tag_group_name
  ON tag_group(name COLLATE NOCASE) WHERE deleted_at IS NULL;

CREATE TABLE IF NOT EXISTS tag_group_member (
  tag_id    TEXT PRIMARY KEY REFERENCES tag(id) ON DELETE CASCADE,
  group_id  TEXT NOT NULL REFERENCES tag_group(id) ON DELETE CASCADE,
  position  INTEGER NOT NULL DEFAULT 0,
  added_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS ix_tgm_group ON tag_group_member(group_id, position);
```

### 8.1 不变量

1. **一个标签只属于一个组**：`tag_group_member.tag_id` 是主键，由数据库强制，不靠应用层检查。
2. **标签在创建时定组**：新建标签必须带 `group_id`（或显式 `unfiled`）。已有标签补组走标签库。
3. **合并标签**：`item_tag` 改写后，成员行从旧标签迁到保留的标签；旧标签软删、写入 `tag_alias`。成员行不能残留指向软删标签（读时过滤 `deleted_at IS NULL`）。
4. **删除组**：软删组 + 删除其成员行（标签转为未分组）；需要确认，并显示影响的标签数与篇数。
5. **改组名 / 组顺序**：只改 `tag_group`，不动标签。
6. 组顺序按 `position` 升序；新组排末尾。未分组永远在末尾之外，不参与排序。
7. **检索按标签 id，不按名字**：`/api/items` 每条带 `topicIds`（名字另给一份 `tags.topic`，只用于显示）。改名和合并都会让名字变，id 不会；名字当身份的话，保存的视图会在下次打开时静默少一个项。`tests/test_retrieval_contract.py` 锁住这一条。

## 9. 智能视图 = 存引用

`saved_view.filter_json` 存**引用**（组 id、标签 id、年份区间），不存快照、不存 `item_ids`。

```jsonc
{
  "v": 1,
  "join": "and",
  "groups": [
    { "kind": "tag",  "group_id": "grp_1", "op": "any",  "terms": ["tag_1", "tag_2"] },
    { "kind": "tag",  "group_id": "grp_2", "op": "all",  "terms": ["tag_3"] },
    { "kind": "tag",  "group_id": "@unfiled", "op": "none", "terms": ["tag_4"] },
    { "kind": "year", "op": "any", "terms": [ { "range": [2019, 2021] }, { "unknown": true } ] },
    { "kind": "attr", "op": "any", "terms": [ { "status": "read" }, { "star": true } ] }
  ],
  "q": "",
  "sort": "year"
}
```

- `terms` 为空 → 该组不参与。
- 视图里只存 `terms`，不存 `options`：可点的项由标签库 / 数据现算。把选项全集也存进去，等于给视图留了一份标签快照。
- 标签合并后，视图里保留的标签 id 不变；被合并掉的 id 失效 → 该视图少一个项，**不报错**，并在打开时提示「有 1 个标签已不存在」。
- 组被删除 → 该组条件失效，同上提示。
- 模式（未打标 / 待补全）**不进视图**。
- 旧的 `filter_json` 从未被任何代码写入（`saved_view` 目前无写入路径），所以不需要兼容旧格式。
- `filter_json` 的顶层与内核的过滤器契约一致：`{ v, q, groups: [{ kind, group_id, op, terms }] }`；`sort` 落在 `saved_view.sort` 列，不重复存进 JSON。

## 10. 冷启动

库小、标签少时，检索台没有任何可点的东西。处理方式：

1. **组区不隐藏**：空的标签组不画，画一块虚线占位「还没有分组。打标签时选一个组，它就会出现在这里」+ 「＋ 新建分组」。
2. **属性条照常**：年份、阅读状态本来就有数据。
3. **动作条优先**：`未打标 64` / `待补全 60` 是空库时唯一的大数字入口，点进去是可执行的。
4. **不设标签数阈值自动切换形态**：首页形态固定，靠内容增长而自然变好。
5. **库全空（0 篇）**：只说一句「书库还是空的」+ 导入入口。

### 11.1 打标加速的规则

- **组记忆**：选过的组写进 `localStorage`（`colophon.group`），下次打开阅读器侧栏直接选中。记住的组被删除时**不静默改投**，而是清掉记忆、回落到未分组。选「未分组」**不**覆盖记忆——否则一次临时存放会把惯用的组冲掉。
- **快捷标签**：当前组里的标签按使用次数排序取前 12 个，点一下即加；这篇已有的显示为置灰禁用。
- **补全顺序**：datalist 先列当前组的标签，再列其余组的，重复项去掉。
- 快捷标签只做**添加**，不做勾选。移除仍靠标签上的 ×。

### 11.2 已知尚未做的（别当成已完成）

- **首页还是旧版面**：左栏分面 + 常驻详情，不是检索台的组区 / 表达式条 / 紧凑行 / 详情抽屉。检索内核已就位（§11 的 7a），界面还没接上。
- **作者 / 单位仍是左栏分面**：§1.4 要的是「不进组区」，等 7b 换版面时一起挪。
- **标签库里的拖拽分组**：目前用「未分组 → ↗ 归入」和「删除组」，没有拖拽。
- **组颜色/顺序编辑**：`tag_group.color/position` 已存库，但界面还不能改。
- **近重复标签的自动提示**：标签库只列出同组标签，不会主动指出「Doherty / 非对称 Doherty」相似。
- **「抓取元数据」不会自动补摘要**：摘要仍要手填，或抓取时由 PDF 首页文本带出来。
- **快捷标签上限 12**：组里超过 12 个标签时，其余的只能靠输入框（有补全）。
- **单位清洗只到「去实体 / 去前导标记 / 标出截断」**：同一机构的不同写法（「ETH Zurich」与「ETH Zürich, Switzerland」、「Glasgow, UK」与「Glasgow, U.K.」）还不会自动合并，需要在「手动合并」里做。
- **清洗不碰正文片段里的中文 / 土耳其语残句以外的判断**：只按词表拦，不按语言识别。
- **清洗是整表一次性应用**：不能撤销，也没有改动历史。

## 13. 数据清洗（作者 / 单位）

元数据抓取会把 PDF 文本层的噪声带进作者与单位，检索时这些脏词会成为干扰项。

### 13.1 规则（`app/clean.py`）

| 档 | 含义 | 默认 |
|---|---|---|
| `auto` | 去上标 / 脚注 / 编号、修重音（`´u`→`ú`）、解 HTML 实体、去前导标记 | 预选 |
| `review` | 像人名但没证据：尾部单字母对不上任何已有作者、单位以虚词结尾 | **不预选** |
| `drop` | 不是人名：邮箱、机构词、地名、正文片段 | 预选 |
| `keep` | 不动 | — |

### 13.2 「尾部单字母」只在有证据时动手

`Yuan Dingb` 的 `b` 是归属标记，但 `Jing Xia` 的 `a`、`Kaushik Sengupta` 的 `a` 是姓氏本身。
两者无法从字符串本身区分，因此规则是：**去掉尾部单字母后，只有在库里已经存在同名作者时才合并**；找不到同名就保持原样。
这条规则在真实库上验证过：`Bo Liua → Bo Liu`、`Haijun Fanb → Haijun Fan` 合并了，`Jing Xia` 一处没动。

### 13.3 不自动做的事

- 不猜 OCR 错字（`Carletan Ihiversity` 保持原样）。
- 不合并同一机构的不同写法（需要语义判断，放在「手动合并」里）。
- 不碰正文片段以外的语言判断。
- 应用后没有撤销。清洗前请先备份 `library/`。

### 13.4 入口

标签库 → 「数据清洗 → 检查」。逐条可改判为「改为 / 删掉 / 保留」，只应用改动过的条目。

## 15. 阅读时打标签

打标签必须能一边翻原文一边做：只看标题打标，等于凭印象猜。

**唯一的标签写入口就是阅读器右侧栏。** 详情面板只读（可筛、可删、可跳去原文），未打标工作台只当队列，列表行也没有行内打标。理由不是审美：三个写入口曾经意味着三份「新建组」状态和三套组解析，其中一套把用户填的组名静默丢掉（见 §15.5）。

例外只有一处：条目**没有托管 PDF** 时，右侧栏照常可用，但顶部写明「没有托管 PDF · 只能凭标题和摘要打标」——这是无原文时唯一能做的事，不假装它和读原文一样准。

### 15.1 形态

阅读器内嵌一条右侧栏（`#readerSide`，318px），**不遮挡原文**，PDF 按剩余宽度自动适应：

- 顶部：`正在读 · 第 N / M 页`（翻页 / 滚动时只更新这一行，不重绘面板，否则输入框会被打断）
- 阅读状态三态 + 星标
- 已打标签（每个可点 × 就地移除）；悬停显示标签的一句话定义
- 新标签：组选择器 + 输入框（回车即加，**停留不跳**）+ 当前组快捷标签
- AI 建议：生成候选、采纳（采纳走**未分组**，§5）、忽略；再生成时把忽略过的放回来
- 底部：补元数据入口、保存状态

顶栏「标签」按钮与 `T` 键切换侧栏；≤900px 时侧栏改为覆盖整块阅读区（不把 PDF 挤成一条）。

### 15.2 和未打标工作台的关系

工作台只做两件事：决定「这一篇该不该打」、看出「元数据缺什么」。它一次只显示一篇，元数据条给「抓取元数据 / 手动补全」，主按钮是「打开原文打标 →」，进阅读器并带着侧栏；关掉阅读器仍回队列。工作台自己**不能加标签**——要标就得进阅读器。

### 15.3 组和快捷标签为什么不再按面板分份

`quickTagsHTML(p, prefix)` 与 `paintQuickOptions(listId)` 只有一个调用方（阅读器侧栏），行为没有第二个副本可比，也就不存在「同一个组在两个界面里排序不同」。

### 15.5 打标面板的组状态

「新建组」状态只有 `state.readerGroupNew` 一份：

- `isNewGroupMode()` / `setNewGroupMode(on)` 是唯一入口。
- `groupFrom()` 的返回值有四种，必须分得开，不能合并成「null 等于未分组」：
  - `{id}` — 选中已有组
  - `{id:null}` — 显式选「未分组」
  - `{id:null, name, isNew:true}` — 新建组（组名一起提交，后端一次建组 + 打标）
  - `undefined` — 处于新建组模式但组名还没填，**调用方必须停下列出提示**
  - `null` — 面板控件不在（正在切换），调用方不猜

这一条是踩过坑写下的：`groupFrom` 曾经只检查工作台的 `groupNew`，在阅读器里新建组时返回 `null`，标签被静默丢进未分组，用户填的组名完全没用上。收成一个入口后这类 bug 结构上就没了，但 `undefined` / `null` 的区分仍然要留着。回归测试在 `tests/group_logic.test.js`（`node tests/group_logic.test.js`）。

### 15.6 不做的

- 不在 PDF 上做文本选择 / 高亮（v1 决策 #3 不变）。
- 侧栏不显示当前页的文本摘录——文本层抽取还没接。
- 打标不记录页码：标签属于整篇，不属于某一页。
- 列表行内打标、详情页内打标：没有，也不加回来。

## 16. 明确不做

- 相关度排序、语义 / 向量检索（标签是用户词汇，布尔是确定语义）。
- 标签父子层级（分组是**一个**归属，不是树；与 `docs/v1-spec.md` 决策 #2 一致）。
- 跨组 OR、全局 AND/OR 开关、组内混合正负。
- 自动打标（AI 建议必须采纳才写入）。
- 标签的「同义词」视为一个项（合并即可，别名只用于输入补全）。
